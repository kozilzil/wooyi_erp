# 09-testing-strategy

## 1. 테스트 목표
- 핵심 회계 규칙 오류 방지
- 권한 누락 방지
- CRUD 및 검색/필터 기본 회귀 방지
- 문서와 구현의 불일치 최소화

## 2. 백엔드 테스트 우선순위

### P0
- 로그인/권한
- 회원 등록/조회/수정
- 복식부기 합계 검증
- 전표 승인/취소
- 기간 마감/재개방

### P1
- 출석 등록
- 비품 등록/수리 이력
- QR 내보내기
- 파일 업로드

## 3. 프런트 테스트 우선순위

### P0
- 로그인 폼
- 회원 등록 폼
- 전표 등록 폼
- 승인 화면 액션
- 비품 등록/QR 내보내기 화면

### P1
- 검색/필터
- 목록 페이징
- 공통 모달/알림

## 4. 최소 실행 명령 예시

백엔드:
```bash
cd backend
./gradlew test
```

프런트:
```bash
cd frontend
npm run lint
npm run test -- --runInBand
npm run build
```

## 5. 회계 테스트 시나리오 필수 목록

1. 복식부기 차변/대변 불일치 저장 실패
2. 승인 없는 전표가 장부에 반영되지 않음
3. 승인 후 장부 생성
4. 취소 후 장부 역처리
5. 마감 후 수정 금지
6. 재개방 후 수정 가능

## 6. PR 머지 기준
- P0 테스트 실패 시 머지 금지
- 문서 갱신 누락 시 보완 후 머지
