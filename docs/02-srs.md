# 02-srs

이 문서는 상세 기능명세서의 상위 템플릿이다.
실제 구현 시 기능 ID별로 세분화하여 확장한다.

## 기능 명세 형식

- 기능 ID
- 기능명
- 목적
- 사전 조건
- 입력
- 처리 규칙
- 예외 규칙
- 출력
- 권한
- 감사로그 여부
- Acceptance Criteria

---

## 예시 1: 회원 등록

- 기능 ID: MEM-CORE-001
- 기능명: 성도 기본 등록
- 목적: 신규 성도의 기본 정보를 저장한다.
- 사전 조건: 로그인 사용자가 회원 등록 권한을 가진다.
- 입력: 이름, 성별, 생년월일, 연락처, 주소, 등록일, 부서, 구역, 직분
- 처리 규칙:
  - 이름은 필수다.
  - 연락처 형식 검증을 수행한다.
  - 부서/구역/직분은 공통코드 또는 참조 테이블 값이어야 한다.
- 예외 규칙:
  - 중복 회원으로 의심되는 경우 경고를 표시한다.
- 출력:
  - 회원 상세 정보
  - 생성 성공 메시지
- 권한:
  - 시스템 관리자
  - 교적 담당자
- 감사로그 여부: 예
- Acceptance Criteria:
  - 유효한 입력으로 저장 가능
  - 필수값 누락 시 저장 실패
  - 생성자/생성일 기록
  - 감사로그 기록

---

## 예시 2: 복식부기 전표 승인

- 기능 ID: FIN-VOUCHER-APPROVE-001
- 기능명: 복식부기 전표 승인
- 목적: 승인된 복식부기 전표만 장부에 반영한다.
- 사전 조건:
  - 사용자는 승인 권한이 있어야 한다.
  - 전표 상태는 `DRAFT` 또는 `REQUESTED` 여야 한다.
- 입력:
  - 전표 ID
  - 승인 의견(선택)
- 처리 규칙:
  - 차변 합계와 대변 합계가 같아야 한다.
  - 마감된 회계기간이면 승인 불가
  - 승인 시 상태를 `APPROVED`로 변경
  - 승인 이력 기록
- 예외 규칙:
  - 합계 불일치 시 승인 실패
  - 권한 없음 시 403
- 출력:
  - 승인 결과
  - 최신 전표 상태
- 권한:
  - 재정 담당자
  - 재정 관리자
- 감사로그 여부: 예
- Acceptance Criteria:
  - 승인 성공 시 장부 조회 대상에 포함
  - 승인 실패 시 상태 유지
  - 감사로그와 승인 이력 모두 저장
